# ФОРМА · Нодовый рабочий процесс (ориентир VizMaker)
Дата: 2026-11-14. Целевая ветка: `dom-render-nanobanana`. Основной адрес: `/forma-preview.html`.
Этот документ — спецификация самостоятельной реализации, а не копия исходного кода VizMaker.

## Цель
Все 17 инструментов остаются в ФОРМА. Центральный инструмент — нодовый холст, где результат каждой операции становится входом следующей. Пользователь должен видеть версии изображений, разветвлять цепочки и запускать выбранный этап без перехода на внешний сайт.

## Реализовано в текущей ветке
- Ноды с входами и выходами, отдельные ветки, запрет циклов, перетаскивание узлов, соединение портов жестом и кликом; автоматическая компоновка и масштабирование.
- Настройки выбранной ноды в отдельном инспекторе, без кнопки «Открыть ↗» и переходов в соседние приложения.
- Чтение реального пользовательского скриншота и настроек текущего проекта из ДОМ.РЕНДЕР; демо-исходник для платных AI-запросов запрещён.
- Экстерьер, интерьер, свет и изменение материала по текстовому заданию через существующий `/api/render` и серверный API Market. Каждая платная операция требует подтверждения. Запросы не имитируются.
- Сохранение результатов узлов в IndexedDB, до пяти сохранённых версий кадра на узел, восстановление версии, повторное использование без нового AI-вызова.
- A/B просмотр двух готовых кадров; автоматическая запись успешной AI-цепочки в галерею проекта.
- Локальное наложение исходника для визуальной проверки геометрии (не инженерный геометрический контроль).
- Локальное масштабирование изображения до 3840 px (не AI super-resolution); экспорт изображения.
- Видео-нода через сервер `/api/wan/*` при настроенном OpenRouter Wan 2.6, с проверкой доступности/лимита, опросом задания, сохранением MP4 в IndexedDB и скачиванием.
- Отмена/повтор до 70 шагов графа; JSON-импорт и экспорт структуры графа и его параметров.
- Главная панель 17 инструментов: подходящие действия добавляются в схему; PRO-панели остаются встраиваемыми, GLB-мир показывается во фрейме той же страницы.
- Проверены синтаксис модулей и связи функций на уровне исходного кода.

## Ограничения, которые нельзя выдавать за реализованные функции
- Генерация 3D из фото: нет подключённого Meshy/Tripo-совместимого движка; нода показывает недоступность, а не фальшивый .glb.
- AI-увеличение детализации / area upscaler уровня Magnific: локальные 3840 px сейчас только интерполяция.
- Прямое получение viewport из Revit/SketchUp/Archicad: требуется отдельный плагин к desktop CAD или импорт файлов; загрузка скриншота работает.
- Рисование масок, стрелок и вложенных reference-изображений прямо внутри нодового холста (в основной ФОРМА уже есть отдельный редактор масок, но в нодовый он ещё не перенесён).
- Text-to-image без исходного изображения: текущий image-edit backend требует входное изображение.
- Сохранение переносимого проекта вместе со всеми MP4/изображениями одним архивом: текущий JSON хранит схему и параметры, изображения сохраняются в браузере по проекту.
- Полнопрограммный контроль архитектурной геометрии: AI не может гарантировать точность окон/венцов/размеров без CAD-движка.
- Сквозные e2e-тесты живого браузера и фактические успешные обращения к платным AI-провайдерам пока не выполнены.

## Конфигурация
- Изображения: `API_MARKET_KEY` хранить только в Render Environment.
- Видео Wan 2.6: `OPENROUTER_API_KEY` и `WAN_VIDEO_ENABLED=true`, с лимитами и согласованием стоимости.
- Для Wan 3.0 отдельный защищённый режим согласно `WAN3_ALIBABA_SETUP.md`; нельзя незаметно переключать или вызывать платную модель.
- Не передавать API-ключи в HTML, фронтенд, GitHub или сохранённые ноды.
- Render сервис `dom-render-nanobanana`, ветка `dom-render-nanobanana`, автодеплой настроен в Render. Проверять последний коммит реального деплоя, а не только `main`.

## Ручная проверка перед релизом
1. Открыть `/forma-preview.html`; убедиться, что браузер загрузил новую версию JS и CSS и что нет блокирующего баннера статического предпросмотра на Render.
2. Создать новый проект, загрузить PNG/JPG скриншот. Открыть ноды, соединить «Исходник → Экстерьер → Свет → 4K → Экспорт».
3. Запустить выбранную ветку при готовом /api/status: получить реальные кадры в узлах и галерее; без API — понятную ошибку, без фиктивного фото.
4. Сравнить A/B, изменить атмосферу и повторить; проверить сохранение прежнего результата и восстановление его из истории без нового вызова.
5. Перезагрузить страницу и открыть ноды: прошлые данные должны восстановиться из локального браузера.
6. Добавить видео-ноду: без видео API показывать причину; с доступным API получить настоящий MP4.
7. Проверить touch-управление, видимый инспектор, прокрутку и кнопки в Android Chrome.
8. Проверить, что переходы в другие сайты из карточек инструментов отсутствуют.
