# FORMA VISUAL · DOM.RENDER — АЛЬФА
## Суперточное техническое задание: реальная толщина фронтонной стены, утопленные окна, наружные/внутренние откосы

Дата: 22.11.2026. Ветка: `dom-render-nanobanana`. Статус: **ТЗ, не реализация**.

### 0. Проблема и цель
По фактическому мобильному скриншоту DOM.RENDER фронтон A-frame выглядит как плоский лист, а панорамные окна/раздвижные двери — как накладные стеклянные плоскости. Не читаются глубина стены, откосы, наружные четверти, посадка оконной рамы и нижние узлы. Исправить геометрию, не изменяя силуэт и место дома. Цель — убедительный масштабный архитектурный узел в реальном Three.js-редакторе, а не отдельная иллюстрация.

- `forma-landscape-3d-alpha-windows.js`: `addAlphaGlazedFacade`, `addAlphaVisibleInterior`. Убрать фронтально навесное положение стекла и ВСЕХ профилей, унифицировать через единую систему Z.

### 2. Реальные исходные значения в текущем коде
Стандартный референс: ширина `w=7.5` м, глубина `d=9.5` м; `rise=w*0.79≈5.925` м; `eave=0.65` м; `half=w/2+0.22=3.97` м. Длина/ширина и положение самого дома изменяемы пользователем — никакой жёсткой привязки геометрии к 7.5 м.
- `front=d/2+0.058`, положительное локальное направление `+Z` — НА УЛИЦУ; `-Z` — В ИНТЕРЬЕР.
- Наружная плоскость текстурированного фронтона сейчас `zOuter = front + 0.006`.
- `glassBase = eave + rise*0.347 ≈ 2.706` м; `glassHalf = half*(1-(glassBase-eave)/rise)-0.12 ≈ 2.472` м; `glassTop = eave+rise-0.34 ≈ 6.235` м.
- `doorWidth = min(w*0.67,max(2.3,w-1.1)) ≈ 5.025` м; `doorBottom = 0.49` м; `doorTop = min(glassBase-0.11,2.61) ≈ 2.596` м.
- Сейчас стекло фронтона стоит на `front+0.040` и `front+0.083`, а дверь на `front+0.052` и `front-0.013`; рамы и уплотнения вынесены ещё дальше наружу. Это ошибка: **вся оконная система должна быть внутри стены**.
- В `alphaFacadePanel` уже существуют настоящие треугольный и дверной проёмы `ShapeGeometry.holes`. Не перекрывать их новыми непрозрачными плоскостями.

### 3. Единая геометрия и координаты (главный обязательный контракт)
Ввести константы/конфигурацию `ALFA_OPENING_DETAIL` (в метрах), а не копировать магические значения во множество функций:

| Параметр | Номинал | Назначение |
|---|---:|---|
| `wallThickness` | `0.240` | Визуально геометрическая общая толщина фронтонного стенового узла |
| `claddingThickness` | `0.020` | Толщина видимого торца облицовки, НЕ отдельных досок на фасаде |
| `ventGap` | `0.030` | Представление вентзазора только в разрезах откоса, без детального моделинга |
| `frameRecess` | `0.140` | Отступ лицевой плоскости оконной рамы внутрь от наружного фасада |
| `frameFaceWidth` | `0.060–0.075` | Видимая ширина алюминиевой рамы |
| `frameDepth` | `0.075–0.085` | Глубина профиля по Z, не путать с шириной на фасаде |
| `glassUnitThickness` | `0.032` | Визуально двойной стеклопакет 6–20–6 мм; 2 отдельных стеклянных листа, дистанционная рамка |
| `paneThickness` | `0.006` | Толщина каждого слоя стекла |
| `sillSlope` | `3°–5°` | Наклон наружного нижнего отлива в сторону террасы |
| `dripProjection` | `0.025–0.035` | Вынос капельника относительно внешнего края облицовки |
| `revealTolerance` | `0.003` | 3 мм допуск на стыки; не допускать заметных световых щелей |

Система Z:
```js
const zOuter = front + 0.006;                  // Плоскость графитовой PBR-облицовки
const zInner = zOuter - wallThickness;          // Обратная, интерьерная поверхность
const zFrameFront = zOuter - frameRecess;       // Передняя кромка установленного оконного блока
const zGlassOuter = zFrameFront - 0.010;        // Центр наружного листа стекла
const zGlassInner = zGlassOuter - 0.026;        // Центр внутреннего листа: 6+20+6 = 32 мм
```
Точность: наружная лицевая часть рамы НЕ должна иметь Z больше `zOuter - 0.125` (с учётом малых накладок); стекло НЕ выступает перед рамой. Все уплотнители, переплёты, ручки/направляющие сдвинуть за рамой согласованно. Контроль: если `zOuter≈4.814` м, то передний край рамы `≈4.674` м, а стекло `≈4.664` и `≈4.638` м. Фактический zOuter пересчитывается по параметрам каждого дома.

### 4. Стеновой пирог и торцы
1. Сохранить существующий **единый UV/PBR графитовый фасад** как наружный слой. Никогда не возвращать отдельные 3D-доски: их полосатость уже была забракована.
2. Создать параллельный **внутренний контур фронтона** на `zInner` из `ShapeGeometry` с ТОЧНО ТАКИМИ ЖЕ двума отверстиями (двери, треугольное остекление), но с отдельным светлым/тёплым внутренним материалом; не клонировать переднюю стену непрозрачным треугольником.
3. Периметр фасада по наружному треугольнику и нижней линии связать торцевыми поверхностями между `zOuter` и `zInner` (не сплошным BoxGeometry внутри проёмов). Угловые торцы закрыть; отсутствие обратной плоскости недопустимо.
4. Добавить *профильные откосы* по контуру обоих проёмов, направленные внутрь; наружный материал — графит/металлическая планка, внутренний — тёплый матовый интерьерный материал. При движении камеры сбоку читается реальная толщина 240 мм.
5. Вентиляционный зазор и облицовочный слой могут быть показаны **в торцевом срезе/откосе** 2–3 полосами/поверхностями. Не моделировать реальный инженерный пирог каждого материала в глобальной 3D-сцене.
6. Внутренний контур НЕ должен пересекать антресоль, внутренние стропила и мебель — при необходимости скорректировать только их локальный отступ от фасада. Стены должны иметь `castShadow` и `receiveShadow`.

### 5. Нижний дверной портал (4 полотна)
- Сохранить текущие размер и количество: четыре прозрачных полотна, исходная ширина `doorWidth`, низ `0.49`, верх `doorTop`. Не менять ширину и координаты проёма относительно оси X.
- Создать четыре отдельных откоса **из боковых, верхней и нижней поверхностей** между `zOuter` и `zFrameFront`:
  - боковые откосы: X по краям `±doorWidth/2`, высота `doorTop-doorBottom`; 
  - верхний: Y=`doorTop`, полный дверной пролёт;
  - нижний: Y=`doorBottom`, герметичная база, переход к существующей террасе.
- Добавить настоящую визуальную **четверть** наружного примыкания: листовой графитовый профиль шириной 25–40 мм, толщиной 3–5 мм; он не перекрывает световой проём.
- Утопить ВСЕ `alpha-sliding-*` детали в `alpha-windows.js` по единой координатной функции. Включая верхнюю перемычку, вертикальные рамы/импосты, стекло (два листа каждого полотна), дистанционные рамки, уплотнения, верхний и нижний направляющие профили, ручки.
- Наружные откосы оставить **тёмные матовые**; внутренние сделать слегка светлее. Запретить светлые бежевые гигантские балки непосредственно поверх рамы.
- У порога предусмотреть две направляющие, выемки для отвода воды, анодированную защиту верхней кромки, небольшой уклон кнаружи. Не делать опасную высокую ступень/брус поверх нынешнего уровня террасы.
- Сам стеклопакет читается как **6 + 20 + 6 мм**. Визуально стекло нейтральное, умеренно отражающее, а не непрозрачная сине-серая пластина; `depthWrite=false`; `castShadow=false` для стекла, без Z-fighting.

### 6. Треугольный витраж
- Использовать **одну и ту же точную треугольную геометрию отверстия** для наружной и внутренней стен: базовая ширина `2*glassHalf`, основание `glassBase`, вершина `top`. Для номинала: ширина `≈4.944` м, высота `≈3.529` м.
- Между наружным контуром (`zOuter`) и посадкой рамы (`zFrameFront`) построить три откосные поверхности: 2 наклонных, 1 горизонтальную по основанию. Сохранить ровный стык у вершины; никаких заглушек через стекло.
- Два слоя треугольного стекла поместить на `zGlassOuter` и `zGlassInner`. Их границы должны совпадать с проёмом с технологическим зазором 10–20 мм под уплотнение.
- Сместить **все** 3 вертикальных импоста, 2 горизонтальных ригеля, наружные косые рамы, уплотнители и декоративный деревянный контур внутрь относительно `zOuter`. Примыкание дерева не должно выступать перед графитовой облицовкой.
- Профиль по наклонному контуру: ориентир видимой ширины 65–80 мм; импосты 45–60 мм, без чрезмерно толстых рёбер. Зазор по уплотнению 6–12 мм. Нижний профиль 70–90 мм с отводом воды.
- Внутренние A-образные несущие деревянные балки располагаются **глубже внутреннего стекла** — не пересекают стеклопакеты и не «приклеены» к фасаду.
- Сохранить верхнюю небольшую зашитую вершину A-frame. Её закрытие и стык с кровлей также должны иметь реальную толщину.

### 7. Кровля, доборы, низ стены
- Не менять двускатный A-frame силуэт, уклон и 4 мансардных окна.
- По наружным наклонным торцам кровли показать толщину пирога 180–240 мм визуально: торцевая ветровая планка/обшивка, затем нижний подшив; объём не должен вырастать как толстая декоративная балка.
- На стыке A-образной кровли с фронтонной стеной — непрерывный металл/обрамление, без видимой дырки в интерьере.
- Не менять фундамент/отметку `0.48–0.49` м и геометрию террасы. Стык дверного порога и настила выполнить без пересечений.

### 8. Материалы и качество
- Графитовая фасадная отделка — текущая `alphaGraphitePBR`; НЕ заменять обратно 3D-рейками.
- Профили — нейтральный тёмный графит `#252D30` / `#30383B`, умеренно матовые (`roughness 0.34–0.5`, металл по фактической поверхности).
- Откосы снаружи темнее фасада на ~5–10% по воспринимаемой яркости, без экстремального контраста.
- Стекло: нейтральное (без молочного голубого), лёгкие отражения окружающего неба/деревьев, интерьер читается за стеклом; ночной режим — тёплое свечение из интерьера, не светящийся наружный стеклянный лист.
- Исключить двойные копланарные плоскости (Z-fighting), протечки света, щели >3 мм, прозрачные материалы с непрозрачными тенями. Проверить фронт и 3/4 при ярком солнце и в пасмурный день.
- Сохранить ресурсы для Android: инстансинг где нужен, минимум отдельных мешей, общие материалы и текстуры, освобождение ресурсов после rebuild.

### 10. Проверка, автотесты и приёмка
**Геометрические assertions:**
- `zOuter - zFrameFront` = `0.14 ± 0.005` м.
- `zOuter - zInner` = `0.24 ± 0.005` м.
- Ни у одного наружного стеклянного листа `z` не больше `zFrameFront` (кроме отдельных ручек/планок, если они всё ещё в толще проёма).
- У передней и внутренней фасадных стен по **два совпадающих отверстия**.
- Ровно четыре наружных и четыре внутренних дверных стеклянных полотна; у треугольного витража минимум два слоя. Четыре отверстия в кровле сохранены.
- Отсутствуют `NaN`, отрицательные габариты, полигоны из 0 площади, перевёрнутые нормали и двухстороннее «запечатывание» окон.
- Никаких новых объектов перед фасадом, перекрывающих открывающиеся полотна.

**Визуальная приёмка (СКРИНЫ ИЗ САМОЙ ПРОГРАММЫ, НЕ генерация):**
1. Общий фронт 3/4 — фасад читается архитектурно, окно реально глубже стены.
2. Крупно левый наружный откос нижней двери — видны ~140 мм глубины.
3. Верхний горизонтальный откос двери с порогом — стекло и рама позади наружного фартука.
4. Крупный 3/4 треугольного витража — видны обе наклонные четверти и тёмные импосты.
5. Сбоку по касательной — видна толщина стенки, нет «бумажной» плоскости.
6. 390×844 Android viewport, вкладка «Сцена» — нет перекрывающих дом плашек; всё работает без значимых падений FPS.

**Регрессии:**
- Главный дом и все объекты остаются в прежних координатах (дом, дорожки, деревья, кусты, светильники, терраса).
- `house=alpha` открывает ту же «АЛЬФУ» и её размеры.
- Остальные типы домов не изменены.
- Выбор объектов, «Удалить объект», сохранение, Undo/Redo продолжают работать.
- Солнечный и ночной режимы без «чёрных» или полностью непрозрачных стёкол.

**Готово** — только когда реальные скриншоты демонстрируют утопленные окна и толщину стен с минимум двух ракурсов, код проверен и Render сообщает `live` для нового коммита. Это визуально-архитектурное ТЗ; инженерная пригодность оконного узла для строительства требует отдельного расчёта/чертежа.
