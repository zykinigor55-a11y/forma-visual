# Wan 2.6 Free через OpenRouter — Forma Визуал

Ветка добавляет страницу `/video` (доступна из меню «Анимация») и серверный endpoint `/api/wan-video`.

## Подключение

В **production runtime того сервиса, где реально развёрнут проект**, задайте **секреты сервера**, не `NEXT_PUBLIC_*`:

- `OPENROUTER_API_KEY` — персональный API-ключ с https://openrouter.ai/settings/keys
- `WAN_VIDEO_ENABLED=true` — включить после проверки ключа и доступа к модели.
- `WAN_DAILY_LIMIT=3` — число попыток в сутки на пользователя, 1–20, по умолчанию 3.

Существующие D1 (`DB`) и R2 (`BUCKET`) должны быть подключены. Страница `/video` использует ту же авторизацию ChatGPT, что и `/api/studio`.

**Важно:** на момент подготовки репозиторий работает на Cloudflare/Site (vinext + `cloudflare:workers`), а не на стандартном сервере Node.js в Render. Если разворачивать на Render, понадобится адаптер для D1/R2 и авторизации; просто задать переменную в Render недостаточно. Не переносите ключ в публичный код.

## Что работает

1. Пользователь авторизуется, загружает JPG/PNG/WebP до 8 МБ и описывает движение камеры.
2. Сервер запрашивает `GET https://openrouter.ai/api/v1/videos/models`, проверяет наличие `alibaba/wan-2.6:free`, `first_frame`, поддержку длительности и соотношения сторон. **Платных альтернатив нет**, неизвестные возможности отклоняются.
3. Исходный кадр кладётся в R2 и передаётся OpenRouter по случайной временной ссылке (срок действия 2 часа).
4. Сервер отправляет `POST /api/v1/videos`, сохраняет идентификатор задания в R2 и возвращает локальный ID.
5. Клиент периодически получает статус через свой защищённый endpoint, который опрашивает `GET /api/v1/videos/{id}`.
6. После завершения видео скачивается через потоковый защищённый прокси, API-ключ остаётся на сервере.

Статус показывается как «ожидание/генерация/готово». Реальных процентов OpenRouter в этом API не гарантирует; искусственные проценты не показываем.

## Ограничения перед запуском

- **Живой вызов не проверен:** OpenRouter-ключ не предоставлен. Наличие страницы модели `alibaba/wan-2.6:free` не гарантирует доступ в конкретном аккаунте и её поддержку image-to-video. При отсутствии нужной модели сайт показывает объяснение и **ничего платного не запускает**.
- Для R2 настройте правило автоудаления объектов `wan-frames/` спустя 1 день, иначе временные исходники останутся в бакете даже после истечения доступа по ссылке.
- Задания `wan-jobs/` сохраняются в R2; задайте подходящее правило хранения, если нужно автоматическое удаление истории.
- Начальное ограничение 3 запуска в день — лишь защита от случайных/массовых повторов, а не коммерческая система тарификации.
- Для реального продукта нужны логирование ошибок без ключей, тестирование доступности провайдера, мониторинг объёма R2 и продуманная политика хранения пользовательских изображений.

## Тестирование

Откройте `/video` после публикации. До настройки ключа увидите «Ожидает подключения» и кнопка генерации останется выключенной. После настройки проверьте `/api/wan-video?action=availability` в авторизованной сессии; значение `ready: true` означает, что в каталоге обнаружена бесплатная модель с поддержкой первого кадра.

Проверка фактической генерации выполняется только после установки серверного ключа.
