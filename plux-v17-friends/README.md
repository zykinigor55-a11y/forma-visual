# ПЛЮХ v17 — «Друзья»

**Статус:** код и SQL-схема сохранены в ветке `plux-v17-photo-chat-music-plan`. Существующий ПЛЮХ на Render не изменён. Реальная связь с пользователями будет доступна после подключения нового проекта Supabase.

## Реализованный модуль

- Экран «Друзья» в меню «Инструменты» с прежним OLED-стилем
- Регистрация и вход по email/паролю с подтверждением почты
- Личный ник, поиск по точному нику, входящие заявки и подтверждение дружбы
- Приватная переписка между подтверждёнными друзьями, обновление каждые 10 секунд при открытом экране
- Обмен PNG/JPG/WEBP до 6 МБ с хранением в приватном bucket
- PostgreSQL RLS: чужие сообщения, диалоги и фото недоступны; приватный `service_role` ни в браузере, ни в GitHub не используется

## Подключение к Supabase

1. Создать новый проект в [Supabase](https://supabase.com/dashboard); выбрать надёжный пароль проекта.
2. В SQL Editor применить `plux-v17-friends/supabase-schema.sql` в новом пустом проекте.
3. В Authentication → Providers включить Email; оставить подтверждение почты. Настроить адрес сайта и URL редиректа, если нужны подтверждения на телефоне.
4. Скопировать **Project URL** и **Publishable Key** (или Legacy anon key). **Не копировать** `service_role`/secret keys.
5. В переменных среды Render перед сборкой добавить:
   - `PLUX_FRIENDS_SUPABASE_URL`
   - `PLUX_FRIENDS_SUPABASE_PUBLISHABLE_KEY`
6. В сборочном скрипте *новой тестовой версии* ПЛЮХ после сборки каталога `plux-published` вызвать
   `node plux-v17-friends/apply-v17.mjs plux-published`.
7. Провести проверку с **двумя настоящими аккаунтами** на разных телефонах: регистрация, переименование ников, заявка, принятие, сообщения, фото.

Клиентские URL и Publishable Key могут присутствовать в статике: безопасность обеспечивает Supabase Auth + RLS. Нельзя публиковать secret, service_role или DB password.

## Особенности и ограничения

- Push пока **не подключён**. Для Android требуются FCM device tokens, явное разрешение уведомлений и серверный отправитель. Полностью выключенный телефон уведомления в реальном времени не принимает; они могут доставиться при включении до истечения TTL.
- Сообщения обновляются опросом раз в 10 секунд, веб-сокеты Realtime ещё не настроены.
- Ограничение частоты дружеских заявок, блокировки и жалобы, удаление аккаунта и модерация нужны перед публичным запуском многопользовательского приложения.
- Диалоговые фото хранятся приватно. Контент не подвергается E2E-шифрованию: оператор Supabase с достаточными правами может получить доступ к данным.
- Режим редактирования своих фото в генераторе требует поддержки image-to-image в серверном API: интерфейс уже подготовлен, но функциональность нельзя считать готовой до проверки бэкенда.
- Прямое сохранение изображений в системную галерею из Android APK требует нативного MediaStore bridge; простое HTML `download` на Android WebView не всегда работает.
- Корректный красный и синий оттенки капли требуют отдельной цветокоррекции видео/материалов, а не переименования кружков палитры.
