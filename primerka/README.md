# ДОМ.ПРИМЕРКА · прототип новой платформы

Русское название нового продукта: **ДОМ.ПРИМЕРКА**. Первый экран для частного клиента: «Посмотрите, каким станет ваш дом». Отдельная ссылка «Для производителей» ведёт в профессиональный кабинет.

## Где открыть

Эта ветка основана на проверенном исходном коде ДОМ.РЕНДЕР (ветка dom-render-nanobanana). Существующий редактор остаётся доступен по корню сайта, а новый интерфейс размещён отдельно:

1. Требуется Node.js 20+.
2. Запустите из корня репозитория: node server.mjs
3. Откройте http://127.0.0.1:3000/primerka/index.html
4. Оригинальный редактор доступен по http://127.0.0.1:3000/

Для будущего Render Web Service: start = node server.mjs, host = 0.0.0.0. Отдельная публикация не выполнялась.

## Готово сейчас (v0.1)

- Русскоязычная адаптивная главная, с приоритетом простого входа частного пользователя.
- Демонстрационный кабинет клиента: фото дома, выбор нескольких материалов, сохранение подборки.
- Демонстрационный кабинет производителя: добавление материала, артикула, компании, цены, цвета, текстуры и категории; удаление материала и экспорт своих позиций в CSV.
- Добавленные позиции автоматически видны в каталоге клиента на том же устройстве.
- Демопозиции нарочно отмечены как ненастоящие; их артикулы с префиксом DEMO.
- Фото уменьшается на устройстве и хранится локально в браузере, не отправляется на сервер.
- Кнопка перехода к отдельному существующему редактору ДОМ.РЕНДЕР.

## Чего НЕТ (важно)

Это **не коммерческий SaaS**: отсутствуют реальные роли, регистрация/авторизация, облачный каталог производителей, отправка заявок, интернет-платежи, 3D GLB-конфигуратор и автоматическое нанесение выбранного артикула на фото. Кабинеты — прототипы. Подборка не передаётся автоматически в старый редактор, который открывается отдельно.

## Следующий технический этап

1. Выделить полноценное приложение и изолировать учётные записи. Общая регистрация, разные роли customer, manufacturer_pending, manufacturer_admin, проверка производителя администратором.
2. База данных: users, organizations, memberships, products (SKU, категория, фото/цвет, цена/единица, регион), projects, project_materials, leads, consents, audit_events.
3. На сервере проверять права на все операции, связывать товары с organization_id, не давать компаниям читать чужие заявки.
4. Загружать медиа в защищённое объектное хранилище, делать ограничения на размер/тип, антивирусную и контентную проверку при необходимости.
5. Интегрировать AI-редактор ДОМ.РЕНДЕР как отдельный сервис визуализации, контролируя бюджет генераций и не гарантируя геометрическую точность только по фото.
6. Пилот с одним реальным производителем и 10–20 SKU, затем заявки с явным согласием на обработку и передачу контактов, аналитика, тарифы, CRM и GLB.

## Изоляция и сохранность

Никаких изменений в старом ДОМ.РЕНДЕР на этой стадии; вся новая страница находится в /primerka/. Секреты API не копируются на клиент. Данные прототипа хранятся только в localStorage текущего браузера, не синхронизируются и не являются резервной копией.
