# ДОМ.ПРИМЕРКА — новая платформа примерки отделки

Ветка: feature/dom-primerka-platform, ответвление от dom-render-nanobanana.

**Назначение:** одна русскоязычная веб-платформа для двух аудиторий. Клиенты загружают фото дома, подбирают материалы и сохраняют проекты. Производители управляют своими реальными артикулами и текстурами; их каталоги становятся доступны клиентам после подтверждения компании.

## Текущий статус — staging v0.2

Реализованы:
- Русскоязычная адаптивная главная, разделы «Подобрать отделку» и «Для производителей».
- Серверные учётные записи клиентов и производителей; при регистрации производитель получает роль manufacturer_pending.
- Подтверждение компании администратором переводит её в approved и пользователя в manufacturer_admin; без подтверждения создавать товары запрещено.
- Доступ к товарам производителей между браузерами через серверную SQLite-базу; изоляция управления по organization_id.
- Реальные атрибуты материалов: название производителя, категория, название, SKU, единица, цена, цвет и миниатюра текстуры.
- Клиентские проекты с загруженной миниатюрой дома и выбранными товарами — в базе, привязаны к пользователю.
- HttpOnly cookie-сессии, scrypt-хеши паролей, проверки прав на сервере, защита от межсайтовых записей, базовое ограничение частоты обращений.
- Удаление товаров из своего каталога, экспорт CSV, демонстрационные примеры с явной отметкой «Демо».
- Старые функции редактора ДОМ.РЕНДЕР и его API остаются на прежних адресах.

**Это тестовая версия, а не готовый публичный сервис.** Отсутствует подтверждение email, защита от спама промышленного уровня, восстановление пароля, 2FA, аудит персональных данных, нормальный админ-кабинет, производственный каталог в PostgreSQL, бэкапы, согласия/лиды, оплаты и само нанесение выбранного SKU на изображение. Фото хранится с ограниченным размером в SQLite без объектного хранилища. Нельзя использовать реальные пароли/персональные данные клиентов до завершения инфраструктуры.

## Локальный запуск (Node 22+)

1. Установите Node.js 22 (встроенный node:sqlite нужен только API ДОМ.ПРИМЕРКА).
2. В отдельном тестовом окружении задайте:
   - PRIMERKA_STAGING_ENABLED=true
   - PRIMERKA_ADMIN_KEY=<случайный секрет минимум 24 символа>
   - PRIMERKA_DB_PATH=<путь до локального приватного файла portal.sqlite>
   - HOST=127.0.0.1
   - PORT=3000
3. Запустите из корня репозитория: node server.mjs
4. Откройте http://127.0.0.1:3000/primerka/index.html
5. Обычный старый редактор остаётся по http://127.0.0.1:3000/

Если PRIMERKA_STAGING_ENABLED не задан, новое API не открывается (HTTP 503). Новая страница покажет предупреждение. Секрет администратора НЕ размещать в браузере, исходниках, переписке или коммитах.

## Проверка и подключение производителя

1. Через страницу нажмите «Войти» → «Регистрация» → «Производитель».
2. Укажите тестовую компанию. Система создаёт роль manufacturer_pending и отдельную организацию.
3. Получите organizationId из тестового аккаунта: GET /api/primerka/me с авторизованной cookie.
4. Администратор подтверждает организацию серверным запросом (подставить своё значение секретного ключа из окружения):
   POST /api/primerka/admin/approve
   Header: Content-Type: application/json
   Header: x-primerka-admin-key: <секрет>
   Body: {"organizationId":"<uuid организации>","approved":true}
5. После подтверждения производитель обновляет страницу, добавляет материалы. Клиент в другом браузере увидит их в общем каталоге.

Секрет администратора не пересылайте клиенту. Для реального запуска заменить эту точку на защищённую операторскую панель.

## Техническое решение и ограничения

- Существующий ДОМ.РЕНДЕР: отдельный Node HTTP-сервер и API-Market AI, без изменений маршрутов.
- Новый API добавлен только по префиксу /api/primerka/. На старых Node 20 загрузка sqlite-модуля отложена до обращения к этому API.
- SQLite подходит для локальной проверки и небольшой однопроцессной демонстрации. На Render без постоянного диска БД исчезнет после перезапуска; нельзя делать публичный запуск в такой конфигурации.
- Перед продакшеном: изолированное приложение и защищённая облачная PostgreSQL-БД, объектное хранилище R2/S3, подтверждение почты, RBAC, аудит, бэкапы, верификация производителей и связка реального SKU с генерацией.
- Не перезаписывать действующий продакшен ДОМ.РЕНДЕР. Разворачивать только отдельный staging-сервис с паролем доступа к предпросмотру.
- Демо-материалы не являются настоящими артикулами. Выбранный SKU пока не отображается физически точно на фото: визуальный редактор ДОМ.РЕНДЕР живёт отдельно.

## Следующий шаг
